# Spec — a worker's non-read MCP call waits for the author

**Contract.** For a Claude Code worker lease, PreToolUse allows kudo's own tools and non-MCP tools unchanged. An external MCP tool whose final name begins with a read-only verb (`get`, `list`, `read`, `search`, `fetch`, `query`, `find`, `describe`, `show`, or `status`) proceeds. Every other external MCP call, including an unknown verb, is parked in the context store with its lease, full tool name, and JSON arguments. The console shows it in the approval queue with allow-once and deny-once verdicts. The hook waits for that request's verdict; approval permits only that invocation, while denial, expiry after 30 minutes, cancellation, or a store failure denies it.

**Chosen.** The context store is the pending-request transport, so the approval path needs neither a hub nor a node. Requests and verdicts are append-only records bound by request id and lease. Only exact single-use approvals are offered for MCP arguments.

**Rejected.** Classifying writes by the MCP server's name. Standing allow rules for arbitrary JSON arguments. Trusting a tool's self-description as proof of read-only behavior. A flat deny for every write when an approval path is available.

**Escape hatch.** Strict MCP still removes external servers entirely. Kimi Code is not wired to this approval flow: its hooks fail open on launch failure or timeout and allow at most 600 seconds, so it cannot satisfy this 30-minute fail-closed contract. This contract governs MCP tool calls only: Bash and other direct network egress require a separate sandbox or proxy policy and must not be described as read-only merely because this hook is active.
