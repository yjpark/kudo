# Spec — an isolated context gives each lease its own worktree

**Contract.** A context created with `new --worktree` is isolated. When a worker for that context names a declared repo, launch creates and enters a git worktree unique to that lease and repo, based on the repo's local `main`. The same path is reused if that lease restarts, so its uncommitted work survives. Workers without a named repo and contexts without the option keep the existing directory behavior.

**Chosen.** Per-lease rather than per-item isolation: one lease already works items sequentially, while parallel workers hold distinct leases. The worktree lives under the context store's worktree directory and is not deleted automatically at lease end, because it may contain the only copy of unfinished work.

**Rejected.** Sharing a checkout among isolated workers. Silent cleanup on submit or session end. Per-item worktrees that a replacement lease could not naturally resume.

**Escape hatch.** Declared repos that do not use local `main`, or that need a different isolation policy, do not use this option; a later base-revision contract can extend it.
