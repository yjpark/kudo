# Decision — upgrade binaryen for the console release build

The console release build should run `wasm-opt` successfully rather than relying on dx's implicit unoptimized fallback. Upgrade binaryen through the existing jig/nixpkgs dependency chain to the newest compatible package available there, then verify `dx build -p kudo-console --web --fullstack --release` completes without SIGABRT.

Rejected: disabling optimization (keeps the larger WASM as a permanent choice), accepting the abort as normal, a custom latest-upstream package (extra maintenance), and searching for a minimum compatible version (more testing than the dependency update requires).

Open: if the existing nixpkgs chain has no compatible binaryen, record that result and choose a dedicated package as a follow-up rather than silently accepting the fallback.
